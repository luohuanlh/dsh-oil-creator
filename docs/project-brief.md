# 项目简报

## 当前重大改造：AI 工作台到平台草稿

- **具体用户事件**：创作者已在本地拥有视频、字幕、文章和封面，希望在 DeepSeek Harness 工作台选定一组素材和目标平台，点击一次后，由当前 Harness 会话中的 AI 补齐各平台标题、摘要、正文与标签，再交给 Ego Browser 在各平台建立可人工复核的草稿。
- **黄金路径**：选择一个可读写的内容目录 → 工作台列出内容子文件夹中的全部可选素材 → 对视频选择“视频 + 可选字幕 + 可选封面”，或对文章选择“Markdown + 封面” → 选择已启用且账号有效的目标平台 → 点击“一键生成平台草稿” → Harness AI 按平台能力生成字段并提交冻结分发包 → Ego Browser 只执行上传、填表、封面处理、保存草稿和结果验证 → 工作台逐平台显示草稿或明确错误；最终发表始终由用户完成。
- **真相来源**：原始视频、字幕、文章和封面以本地内容文件夹为准；素材选择和 AI 平台变体以工作台提交的 `.oil-distribution.json` 冻结分发包为准，重试不得重新改写内容；`~/.dsh-oil-creator/overlay.json` 只保存内容目录、启用平台、账号检查结果和任务状态，不复制原始素材正文。
- **Harness / Ego 边界**：DeepSeek Harness 负责文件选择、读取内容、AI 平台适配、冻结分发包和任务编排；Ego Browser 负责账号任务空间、上传、页面填表、保存草稿与页面验证。Ego 不调用模型、不决定文案，也不点击最终发表。
- **P0 边界**：一种创作者、一个本地内容目录、两种输入模式（视频或文章）、一条“选择素材 → Harness AI 生成并冻结 → Ego 建草稿”的流程；平台只在存在真实适配器且通过草稿回归后才能被标记为远端草稿成功。当前 B站、抖音和快手视频具备真实远端保存和 id 回读证据；微信公众号与百家号图文为“已实现 + 模拟验证，待真实账号回归”；小红书和视频号暂保留为投稿页准备适配器。
- **P0 非目标**：不负责生成、剪辑或烧录原始素材；不提供素材库、云盘同步或发布后数据回收；不自动点击最终发表；不把登录凭据交给模型；不为尚无真实适配器的平台伪造成功；不引入数据库、通用队列、事件总线、第二套浏览器运行时或独立模型配置。
- **成功证据**：用户无需手写 `publish-package.json`；工作台能列出并保存所选视频/字幕或文章/封面；一次操作把选择交给当前 Harness 会话，按平台产生可审计且可复用的冻结字段；Ego 只消费该冻结分发包并停在最终发表前；页面已备与远端草稿采用不同状态；单个平台失败不把其他已成功平台改写为失败；全量测试与构建通过，并至少有一条带远端 id 的真实平台草稿回归证据。
- **重型架构门槛**：只有第二类真实平台适配器稳定存在时才提炼通用页面动作协议；只有真实并发任务出现恢复或资源争用时才引入队列；只有本地文件和轻量 sidecar 无法支撑必需查询时才引入数据库；只有直接使用当前 Harness 会话无法满足可用性时才增加插件专属模型设置。

## 平台接入边界

平台目录参考 `dsh-context-flow` 的 22 平台清单，并补充网易云音乐、喜马拉雅听两个音频入口，合计 24 个账号入口。账号登录流程参考其“账号属于配置层”的设计；草稿安全边界参考 `video-publisher`，任何自动化都必须停在最终发表按钮之前。字幕始终可作为 Harness AI 的语义输入，但只有平台适配器明确支持外部字幕时才上传；公众号图文等文章平台只有在真实 Ego 适配器完成并通过回归后才进入可选分发列表。

## 百家号图文草稿 P0

- **具体用户事件**：已在 Ego Browser 登录百家号的创作者，在图文工作台选择一篇本地文章、一个封面和百家号后，希望得到一个可继续人工编辑的百家号远端草稿。
- **黄金路径**：选择 Markdown 与封面 → Harness 生成并冻结百家号标题、摘要、正文和标签 → Host 将冻结变体转换为纯机械 Ego 输入 → Ego 打开百家号编辑页并确认登录态 → 上传封面、保存草稿 → 从响应取得 `article_id` → 重新打开该草稿编辑页并核对 `article_id` 与标题 → 只在回读成功后写入 `draft` 状态并把页面交还用户。
- **真相来源**：素材与平台字段仍以现有 `.oil-distribution.json` 为唯一真相来源；百家号响应中的 `article_id` 和重新打开后的编辑页是远端成功证据，不新增第二套文章记录。
- **P0 边界**：只增加百家号这一项外部集成；沿用当前基础 Markdown 到安全 HTML 的转换和单封面输入；直接复用现有逐平台图文运行器生命周期，不增加数据库、队列或通用多平台编排器。
- **P0 非目标**：不自动最终发表，不声明原创，不绕过登录、验证码、风控或安全校验；不处理 Markdown 正文内图片搬运，不接入头条号等其他图文平台，不承诺多图、分类、定时发布或多账号。
- **成功证据**：单元与模拟运行器测试覆盖输入冻结、保存请求、错误分类和回读门禁；生产能力先标记为“已实现、待真实验证”。只有真实百家号账号完成一次草稿保存、返回非空 `article_id`，且重新打开页面精确匹配标题后，才能升级为“远端已验证”。

## 公众号与百家号图文并发扩展

- **具体用户事件**：创作者为同一篇文章同时勾选微信公众号与百家号，希望一次操作并发得到两个互不依赖、可分别核对的远端草稿结果。
- **黄金路径**：选择文章与封面 → Harness 为两个平台生成并冻结独立变体 → Host 同时准备并启动两个独立 Ego 任务空间 → 各适配器分别保存、回读并验证远端草稿 → 工作台逐平台显示成功、运行中或明确错误；任一平台失败不取消或覆盖另一平台结果。
- **真相来源**：继续以同一份 `.oil-distribution.json` 冻结包为内容真相；每个平台只使用自己的冻结变体、任务空间、远端 ID 和回读 URL，不新增共享可变任务记录。
- **最小边界**：仅支持当前已有真实适配器的微信公众号与百家号双平台并发；Host 直接并发启动两个现有运行器，不增加通用编排器、队列、数据库、重试系统或跨请求恢复机制。
- **明确不做**：不扩展到尚未接入的图文平台，不自动最终发表，不共享登录凭据或页面输入通道，不因其中一个平台失败而自动重试另一个平台。
- **成功证据**：同一次 `startDrafts` 在任一运行器完成前已启动公众号与百家号两个任务；两个平台分别进入运行中状态；随后可独立写入成功或失败结果；聚焦测试、全量测试和构建通过。

## 统一 Article Publisher 架构

- **具体用户事件**：创作者为同一篇已经冻结的平台文章变体勾选一个或多个已接入图文平台，点击一次后，希望各平台并发创建仅供人工复核的草稿，并分别看到远端 ID、编辑地址或明确阻塞原因。
- **黄金路径**：工作台选择 Markdown、封面和目标平台 → Harness 生成并冻结逐平台变体 → Host 从 `.oil-distribution.json` 读取统一输入 → Article Dispatcher 按平台注册表选择 Adapter → Adapter 依次执行 `inspect`、`saveDraft`、`verify` → Host 按平台独立写回运行中、草稿或错误状态 → 用户在平台编辑页人工复核；任何最终发表动作都不属于该路径。
- **核心对象与真相来源**：本地素材和 `.oil-distribution.json` 继续是文章内容与平台变体的唯一真相来源；平台保存响应中的远端 ID、去敏后的编辑 URL 和重新打开后的标题是远端证据；Adapter 不重新生成、改写或另存平台内容模型。
- **P0 边界**：先用微信公众号与百家号两个已有实现提炼最小 Adapter 契约和注册式 Dispatcher，保持现有逐平台独立 Ego 进程及并发写回；随后只接入具有可靠页面或接口证据、能够明确停在“保存草稿”的平台。每个平台先完成契约测试和本地模拟，再决定是否开放自动草稿能力。
- **明确不做**：不新增数据库、Redis、任务队列、事件总线、定时发布、多账号系统或大型 UI；不为单个平台建立第二套内容生成流程；不把“已实现”“本地测试通过”“页面可达”“远端已保存”“远端已回读”合并为一个模糊状态；不绕过登录、验证码、风控或平台安全机制。
- **成功证据**：微信与百家号不再通过核心 `if/else` 分支选择；统一契约能拒绝缺少阶段或证据的 Adapter；一次多平台请求在任一完成前启动全部可启动平台，部分失败独立写回；平台能力矩阵准确区分本地测试和远端验证；聚焦测试、全量检查、构建及 `git diff --check` 通过。
- **架构证据门槛**：第二个真实图文实现已经出现并显示稳定的“检查 → 保存 → 回读”重复结构，因此允许引入轻量 Adapter 注册表；现有直接并发尚能满足隔离和恢复需求，因此不引入队列或工作流引擎；只有多个 Adapter 再次出现稳定重复后才继续提炼上传、编辑器或认证子协议。
