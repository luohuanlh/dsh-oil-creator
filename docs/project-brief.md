# 项目简报

## 当前重大扩展：OpenScreen 工程兼容

- **具体用户事件**：创作者在内容工作台中把一个真实的 `.openscreen` 工程绑定到某一期，之后从同一入口重新打开工程，并在导出的 MP4/MOV 落到该期目录后继续字幕、封面和发布流程。
- **黄金路径**：选择 `.openscreen` 文件 → `oil_update_content` 沿现有 `studioPath` 接口绑定 → `oil_open_studio` 用系统文件关联打开 → `oil_wait_export` 监视该期目录 → MP4/MOV 稳定落盘后进入成片后的步骤。绑定和打开不改写工程文件；导出仍由用户确认并执行。
- **真相来源**：OpenScreen 工程和媒体以磁盘文件为准；绑定关系继续只存在工作台 overlay 的 `studioPath`，不复制工程内容，不新增工程模型。
- **P0 边界**：一种创作者、一个工程路径、现有绑定接口、一条导出交接路径；同时保持 `.screenstudio` 向后兼容。
- **P0 非目标**：不解析或改写 `.openscreen` JSON，不自动编辑时间线，不自动开始或取消导出，不迁移 `.screenstudio` 工程，不新增数据库、队列或通用录屏后端框架。
- **成功证据**：公开服务接口能够绑定并打开 `.openscreen` 文件；内容目录可自动识别其中的 `.openscreen` 工程；现有 MP4/MOV 稳定落盘监视继续工作；`.screenstudio` 回归测试保持通过。
- **重型架构门槛**：只有第三种真实工程格式出现，且绑定、打开或导出行为已经产生稳定差异时，才提炼通用适配器；只有必须直接操纵 OpenScreen 工程时，才引入格式解析层。
