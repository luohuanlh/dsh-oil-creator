# 项目简报

## 当前重大改造：AI 工作台到平台草稿

- **具体用户事件**：创作者已在本地拥有视频、字幕、文章和封面，希望在 DeepSeek Harness 工作台选定一组素材和目标平台，点击一次后，由当前 Harness 会话中的 AI 补齐各平台标题、摘要、正文与标签，再交给 Ego Browser 在各平台建立可人工复核的草稿。
- **黄金路径**：选择一个可读写的内容目录 → 工作台列出内容子文件夹中的全部可选素材 → 对视频选择“视频 + 可选字幕”，或对文章选择“Markdown + 封面” → 选择已启用且账号有效的目标平台 → 点击“一键生成平台草稿” → Harness AI 按平台能力生成字段并提交冻结分发包 → Ego Browser 只执行上传、填表、保存草稿和结果验证 → 工作台逐平台显示草稿或明确错误；最终发表始终由用户完成。
- **真相来源**：原始视频、字幕、文章和封面以本地内容文件夹为准；素材选择和 AI 平台变体以工作台提交的 `.oil-distribution.json` 冻结分发包为准，重试不得重新改写内容；`~/.dsh-oil-creator/overlay.json` 只保存内容目录、启用平台、账号检查结果和任务状态，不复制原始素材正文。
- **Harness / Ego 边界**：DeepSeek Harness 负责文件选择、读取内容、AI 平台适配、冻结分发包和任务编排；Ego Browser 负责账号任务空间、上传、页面填表、保存草稿与页面验证。Ego 不调用模型、不决定文案，也不点击最终发表。
- **P0 边界**：一种创作者、一个本地内容目录、两种输入模式（视频或文章）、一条“选择素材 → Harness AI 生成并冻结 → Ego 建草稿”的流程；平台只在存在真实适配器且通过草稿回归后才能被标记为远端草稿成功。当前只有 B站视频具备真实远端保存和 id 回读证据；微信公众号图文为“已实现 + 模拟验证，待真实账号回归”；抖音、小红书和视频号暂保留为投稿页准备适配器。
- **P0 非目标**：不负责生成、剪辑或烧录原始素材；不提供素材库、云盘同步或发布后数据回收；不自动点击最终发表；不把登录凭据交给模型；不为尚无真实适配器的平台伪造成功；不引入数据库、通用队列、事件总线、第二套浏览器运行时或独立模型配置。
- **成功证据**：用户无需手写 `publish-package.json`；工作台能列出并保存所选视频/字幕或文章/封面；一次操作把选择交给当前 Harness 会话，按平台产生可审计且可复用的冻结字段；Ego 只消费该冻结分发包并停在最终发表前；页面已备与远端草稿采用不同状态；单个平台失败不把其他已成功平台改写为失败；全量测试与构建通过，并至少有一条带远端 id 的真实平台草稿回归证据。
- **重型架构门槛**：只有第二类真实平台适配器稳定存在时才提炼通用页面动作协议；只有真实并发任务出现恢复或资源争用时才引入队列；只有本地文件和轻量 sidecar 无法支撑必需查询时才引入数据库；只有直接使用当前 Harness 会话无法满足可用性时才增加插件专属模型设置。

## 平台接入边界

平台目录参考 `dsh-context-flow` 的 22 平台清单，并补充网易云音乐、喜马拉雅听两个音频入口，合计 24 个账号入口。账号登录流程参考其“账号属于配置层”的设计；草稿安全边界参考 `video-publisher`，任何自动化都必须停在最终发表按钮之前。字幕始终可作为 Harness AI 的语义输入，但只有平台适配器明确支持外部字幕时才上传；公众号图文等文章平台只有在真实 Ego 适配器完成并通过回归后才进入可选分发列表。
